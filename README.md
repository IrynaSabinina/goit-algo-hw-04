# goit-algo-hw-04
Порівняльний аналіз алгоритмів сортування
Ви протестували Merge Sort, Insertion Sort і Timsort на наборах даних різного розміру (200, 2000, 5000, 10000 елементів) і виміряли час виконання кожного алгоритму.

🧐 Аналіз отриманих результатів
Timsort виявився найбільш ефективним

Поєднання сортування злиттям (Merge Sort) і сортування вставками (Insertion Sort) дозволило Timsort працювати значно швидше.
Він особливо ефективний на великих наборах даних, де перевершує Merge Sort і значно випереджає Insertion Sort.
Insertion Sort працює швидко тільки на малих наборах

Для 200 елементів він майже такий же швидкий, як Timsort.
Проте на 5000+ елементах він стає дуже повільним через свою квадратичну складність 
𝑂(𝑛2)
O(n 2).
Merge Sort показує стабільну продуктивність

Його складність 
𝑂(𝑛log𝑛)
O(nlogn) дозволяє йому добре працювати на великих наборах, але він не настільки швидкий, як Timsort.
✅ Висновки
✔ Timsort — найефективніший варіант для загального використання. Саме тому він використовується в Python (sorted() і .sort()), Java та інших мовах.
✔ Merge Sort варто використовувати, якщо потрібне стабільне сортування (не змінює порядок рівних елементів).
✔ Insertion Sort доцільний лише для малих масивів або майже відсортованих даних
